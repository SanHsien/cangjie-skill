# 阶段 0.5 — 适配预筛选

开工前先判断这份内容该做成完整 skill pack、少量 skill、替代产物,还是不该蒸。不是评价内容"好不好",而是判断产物形态,避免烧掉 30–90 分钟和数万 token 之后才发现没有可执行方法论。

本阶段合并两份上游提案的可执行部分:

- PR #4 的五维评分与四类结论 (`BOOK_FIT.md`)
- PR #22 的复用检查、成本预期与三个坑

默认产出: `books/<slug>/BOOK_FIT.md` (模板 `templates/BOOK_FIT.md.template`),结论同时写入 `PIPELINE_STATE.md`。用户已有可信的适配判断,或在知道取舍后明确要求跳过时,可只在 `PIPELINE_STATE.md` 记录 `prefilter_skipped: true`、理由和确认时间。

## 先查复用

同一本书不需要每个人蒸馏一遍。开始评分前先搜:

1. 本 fork README 已列出的上游／社群示例表
2. 本机已安装 skills (`~/.agents/skills/`、`~/.claude/skills/`、`~/.cursor/skills/`)
3. 宿主有网络和搜索工具时再查 GitHub: `<书名> skill` / `<书名> 蒸馏`

已有现成、质量可接受的产物 → 把链接给用户并询问是否直接安装,跳过流水线。没有 → 继续评分。搜索关键词记进 `BOOK_FIT.md`。

## 成本预期 (评分前告知)

| 内容体量 | 预计时长 | 预计 token |
|---|---|---|
| 短视频 / 短访谈 (<10K 字符) | 10–20 分钟 | 数千 |
| 一本书 (约 20 万字) | 30–90 分钟 | 数万 ~ 十余万 |

这些是量级提示,实际费用取决于模型、上下文和宿主。告知后由用户决定值不值得开跑。用户说停就停,把决定写入 `PIPELINE_STATE.md`。

## 四类结论

| 结论 | 含义 | 下一步 |
|---|---|---|
| `full_skill_pack` | 方法论密度高,适合完整 skill 化 | 进入阶段 0,预估 8–25 个 skills |
| `partial_skill_pack` | 有少量可执行方法,大部分不适合 skill 化 | 进入阶段 0,预估 3–8 个,严格控制数量 |
| `alternate_artifact` | 价值高,但更适合人物库 / 世界观 / 案例库 / 术语库 / 时间线 | 向用户说明替代产物,得到确认才继续 |
| `not_suitable` | 材料不足或目标与 skill 化不匹配 | 停止,除非用户明确要求强行拆 |

## 评分维度

每项 0–5 分,总分 25。分数辅助判断,不能替代理由。每项必须写一句来自目录、章节或文本样本的证据。

| 维度 | 高分信号 | 低分信号 |
|---|---|---|
| 方法论密度 | 有框架、流程、原则、清单、决策规则 | 主要是叙事、抒情、史料、观点散点 |
| 可执行性 | 能转成步骤、判停、输入输出 | 只能"体会"或"欣赏" |
| 迁移性 | 可跨场景复用 | 只在原文单一情境成立 |
| 证据/案例支撑 | 作者多处用案例或反例支撑 | 只有单次表达或漂亮句子 |
| 边界清晰度 | 有反例、适用范围或失败模式 | 方法泛化空间太大 |

建议阈值:

- 20–25: `full_skill_pack`
- 14–19: `partial_skill_pack`
- 8–13: `alternate_artifact`
- 0–7: `not_suitable`

PR #22 的「可蒸性三问」(框架密度 / 原则可复用 / 步骤可拆) 对应上表前三维。≤1 维明显成立时,不要判 `full_skill_pack`。

## 按类型快速判断

| 类型 | 默认判断 | 注意 |
|---|---|---|
| 方法论、管理、投资、运营、写作/设计手册 | 通常 full 或 partial | 仍要防止把常识硬做成 skill |
| 访谈、书信、演讲集 | 通常 partial | 适合抽原则和判断框架 |
| 小说、诗歌、散文 | 通常 alternate_artifact | 更适合人物、世界观、主题、情节结构库 |
| 纯史料、编年、资料汇编 | 通常 alternate_artifact | 更适合时间线、案例库、证据地图 |
| 哲学/思想经典 | partial 或 alternate | 只有能形成可执行判断程序时才做 skill |
| 医学、法律、金融高风险材料 | partial 或 not_suitable | 必须加安全边界,不得替代专业建议 |

## 三个坑

1. **以为模型训练过这份内容就不用蒸** — 蒸馏的价值在触发条件,不在"记住"。该蒸还得蒸。
2. **蒸完就不读原文了** — 蒸馏是阅读的补充。用户没读过时,阶段 1.5 会缺验证背景,让用户多参与确认或先粗读。
3. **Skill 越多越好** — 触发太宽会乱激活。阶段 1.5 宁可多淘汰。目标区间大约 10–25 个/本 (partial 则 3–8),不是 50 个全要。

## 执行步骤

1. 确认用户用途 (完整 skill pack / 少量方法 / 人物或世界观 / 只是探路)。
2. 如果用户已有可信判断或明确要求跳过,记录 `prefilter_skipped: true`、理由和确认时间,然后进入阶段 0。
3. 复用检查 + 成本告知。
4. 读取最小判断材料: 书名/标题、作者、目录、前言或片头、1–2 个代表章节;文本很短可直接读全文。
5. 五维打分,选择四类结论之一,按模板写 `BOOK_FIT.md`。
6. 若不是 `full_skill_pack` 或 `partial_skill_pack`,必须先向用户说明原因和替代方案,得到确认后才进入阶段 0。
7. 更新 `PIPELINE_STATE.md`。

## 质量门

- [ ] 已产出 `BOOK_FIT.md`,五维都有分数和证据
- [ ] 结论属于四类之一
- [ ] 已搜索复用,记录关键词
- [ ] 已告知成本预期
- [ ] 若不是 full / partial,已给替代产物并得到用户方向确认

若用户明示跳过,以上质量门改为检查 `PIPELINE_STATE.md` 是否完整记录跳过理由和确认时间。
